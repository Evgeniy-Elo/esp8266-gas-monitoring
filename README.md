# ESP8266 Gas Monitoring System

Распределённая система мониторинга концентрации газа (MQ-2) на базе ESP8266 Wemos D1 mini.

## 📋 Архитектура системы

### Два варианта реализации:

**1. WiFi TCP/IP версия** (базовая)
- Сервер создаёт WiFi точку доступа
- Клиенты подключаются как WiFi станции
- Связь через TCP сокеты

**2. NRF24L01+PA+LNA версия** (расширенная)
- Беспроводная связь 2.4 GHz
- Дальность до 1000м (с антенной)
- Меньше энергопотребление

## 📦 Оборудование

### Сервер (1 устройство):
- **Wemos D1 mini** (ESP8266)
- **SSD1306 OLED дисплей** 128x64 (I2C)
- **4 светодиода** (разные цвета по желанию)
- **Для NRF24**: NRF24L01+PA+LNA модуль

### Клиенты (4 устройства, ID: 1-4):
- **Wemos D1 mini** (ESP8266)
- **Датчик MQ-2** (аналоговый, питание 5V — см. «Питание» ниже)
- **1 светодиод** (индикация локального состояния)
- **Активный пьезодинамик** (сирена)
- **Для NRF24**: NRF24L01+PA+LNA модуль

## ⚡ Конфигурация

### Общие параметры:
```cpp
#define GAS_THRESHOLD 300            // Порог для MQ-2 raw ADC (0-1023)
#define CH4_THRESHOLD 1000           // Порог метана (PPM) — для methane версии
#define MAX_CLIENTS 4                // Максимум устройств
#define CLIENT_TIMEOUT 5000          // Таймаут отключения клиента (мс)
#define CONNECTION_RETRY_INTERVAL 5000 // Переподключение каждые 5с
```

### Параметры датчика MQ-2 (для methane версии)

Коэффициенты регрессии (`PPM = A × ratio^B`) и сопротивление на чистом воздухе заданы в файлах прошивки (`client_firmware_methane.ino` / `client_firmware_methane_nrf24.ino`).

В проекте используется метан (CH₄), но MQ-2 чувствителен ко всем газам. Ниже — полная таблица из библиотеки MQSensorsLib и даташита:

```cpp
#define RatioMQ2CleanAir 9.83   // Rs/R0 на чистом воздухе (общий для всех газов)
```

| Газ | A | B | Источник |
|-----|---|---|----------|
| **CH₄ (метан)** | **447.71** | **−3.245** | know.smartelements.ru, Example 3 |
| H₂ (водород) | 987.99 | −2.162 | MQSensorsLib ESP32 example |
| LPG (пропан-бутан) — используется | 574.25 | −2.222 | MQSensorsLib MQ-2 example |
| CO (угарный газ) | 36974 | −3.109 | MQSensorsLib ESP32 example |
| Alcohol (этанол) | 3616.1 | −2.675 | MQSensorsLib ESP32 example |
| Propane (пропан) | 658.71 | −2.168 | MQSensorsLib ESP32 example |
| Smoke (дым) | — | — | Использовать CO или LPG кривую |

**Примечание:** Коэффициенты получены аппроксимацией логарифмических графиков из даташита MQ-2 (Hanwei). Значения могут отличаться для конкретного экземпляра датчика. Для смены газа достаточно изменить `setA()` / `setB()` в прошивке — калибровка `R0` общая.

## 🚀 Быстрый старт - WiFi версия (raw ADC)

### Шаг 1: Сервер
1. Откройте `server_firmware/server_firmware.ino`
2. Загрузите на сервер (Wemos D1 mini)
3. Откройте Serial Monitor (115200 baud)
4. Должна появиться информация о WiFi AP

### Шаг 2: Клиенты (повторить 4 раза)
1. Откройте `client_firmware/client_firmware.ino`
2. **Измените DEVICE_ID:**
   ```cpp
   #define DEVICE_ID 1  // Измените на 1, 2, 3, 4
   ```
3. Загрузите на клиент
4. Повторите для остальных (ID 2, 3, 4)

### Результат:
- На экране сервера появятся 4 секции с показаниями
- LED будут гореть/мигать при подключении/alert

## 🚀 Быстрый старт - WiFi версия (метан PPM)

Прошивка `client_firmware_methane` использует библиотеку **MQUnifiedsensor** и выдаёт концентрацию метана (CH₄) в PPM вместо raw ADC.

### Шаг 1: Сервер (тот же, что для raw ADC)
Используйте `server_firmware/server_firmware.ino` — протокол передачи данных (uint16_t) совместим.

### Шаг 2: Клиент
1. Установите библиотеку `MQUnifiedsensor` (см. «Установка зависимостей»)
2. Откройте `client_firmware_methane/client_firmware_methane.ino`
3. **Измените DEVICE_ID:** (1–4)
4. Загрузите на клиент

### Отличия от raw ADC версии:
- На экране сервера отображаются **PPM метана**, а не raw ADC
- Порог срабатывания — `CH4_THRESHOLD` (1000 PPM)
- Калибровка при старте (10 измерений), ручная — командой `calibrate`
- Команды Serial: `status`, `test` (шлёт 1500 PPM), `calibrate`, `restart`, `help`

## ⚠️ Частые проблемы

### WiFi версия

**Клиент не подключается:**
- Проверьте SSID и пароль в config.h
- Убедитесь, что сервер включен
- Попробуйте переподключить питание

**Дисплей не показывает:**
- Проверьте подключение I2C (D1=SCL, D2=SDA)
- Адрес дисплея: 0x3C
- Используйте I2C сканер для диагностики

**Датчик MQ-2 показывает странно:**
- Дайте датчику 5-10 минут на прогрев
- Проверьте аналоговое подключение (A0)
- **MQ-2 требует питание 5V!** Wemos A0 рассчитан на 0–3.3V — необходим делитель напряжения 10kΩ + 20kΩ на выходе датчика (см. «Питание MQ-2 и Wemos» ниже)
- Если methane версия выдаёт 0 PPM при старте — дайте датчику прогреться, затем выполните `calibrate`

**Methane версия выдаёт 0 PPM:**
- Датчик не прогрет — подождите 5–10 мин и выполните `calibrate`
- Сбой калибровки — проверьте, что MQ-2 запитан 5V

### NRF24 версия

📖 См. раздел "Возможные проблемы" в [`docs/NRF24_SETUP.md`](docs/NRF24_SETUP.md)

**Кратко:**
- NRF24 не инициализируется → проверить провода и конденсатор
- Нет связи → проверить адрес "GASMO" и канал 76
- Нестабильно → добавить конденсатор 100nF

## ⚡ Питание MQ-2 и Wemos D1 mini

### Особенности датчика MQ-2
- **Нагреватель требует 5V ±0.2V**, ток ~170 мА
- Аналоговый выход — 0–5V (соответствует 0–1023 для MQ-2)
- Wemos D1 mini A0 принимает **0–3.3V** — необходимо понижение

### Обязательный делитель напряжения
На выходе A0 датчика MQ-2 установите резистивный делитель:

```
MQ-2 A0  ── 10kΩ ──┬── 20kΩ ── GND
                   │
                Wemos A0
```

Формула: `Vout = Vin × 20k / (10k + 20k) = Vin × 2/3`  
5V × 2/3 = 3.33V — в допуск Wemos D1 mini.

### Питание от аккумулятора

| Вариант | Описание | Время работы* |
|---------|----------|---------------|
| **USB Power Bank 5V** | Внешний Power Bank → USB Wemos + параллельно MQ-2 VCC | ~4–6 ч |
| **18650 + MT3608 (Boost to 5V)** | Повышающий преобразователь → 5V → Wemos Vin + MQ-2 | ~4–5 ч |
| **2×18650 последовательно (7.4V)** | → Wemos Vin (до 9V) + MQ-2 через стабилизатор 7805 | ~8–10 ч |
| **18650 с встроенным USB** | Power Bank на одной банке | ~4–5 ч |

\* Время указано ориентировочно для одной банки 2000–3000 mAh, т.к. нагреватель MQ-2 (~170 мА) — основной потребитель.

### ❌ Чего делать НЕ стоит
- **Питать MQ-2 от 3.3V Wemos** — нагрев будет недостаточным, показания нестабильны
- **Питать Wemos от одной 18650 напрямую** — 3.0–4.2V ниже минимума стабилизатора AMS1117-3.3 (требует ~4.5V), Wemos будет работать нестабильно или не включится
- **Подключать MQ-2 напрямую к A0** без делителя — сожжёте вход Wemos (A0 допускает 0–3.3V)

## 📊 Протокол связи

### WiFi TCP:
```
Регистрация:   REG:1\n
Отправка:      DATA:1:245\n
Формат:        DATA:device_id:gas_level
```

### NRF24 (бинарный):
```cpp
struct {
  uint8_t  deviceId;     // 1-4
  uint16_t gasLevel;     // 0-1023 (raw ADC) или 0-65535 (PPM, methane)
  uint32_t timestamp;    // мс
}
```

Значение `gasLevel` передаётся как `uint16_t` — серверу не важно, raw это ADC или PPM.  
Methane версия укладывается в 0–5000 PPM (реальный диапазон MQ-2).
